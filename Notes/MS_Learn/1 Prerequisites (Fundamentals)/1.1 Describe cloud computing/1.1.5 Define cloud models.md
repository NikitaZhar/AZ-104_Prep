What are [[Glossary#Cloud model (deployment model)|cloud models]]? The [[Glossary#Cloud model (deployment model)|cloud models]] define the deployment type of cloud resources. The three main [[Glossary#Cloud model (deployment model)|cloud models]] are: private, public, and hybrid.

![Diagram showing four cloud deployment models with key characteristics for each.](https://learn.microsoft.com/en-us/training/wwl-azure/describe-cloud-compute/media/cloud-deployment-models.png)

## Private cloud

A [[Glossary#Private cloud|private cloud]] is a cloud environment used by a single entity. It evolved naturally from the traditional datacenter model, delivering IT services over the internet while keeping resources dedicated to one organization. [[Glossary#Private cloud|Private cloud]] provides much greater control for your IT team. However, it also comes with greater cost and fewer of the benefits of a [[Glossary#Public cloud|public cloud]] deployment. A [[Glossary#Private cloud|private cloud]] may be hosted from your on-site datacenter, or in a dedicated datacenter offsite, potentially even by a third party.

## Public cloud

A [[Glossary#Public cloud|public cloud]] is built, controlled, and maintained by a third-party [[Glossary#Cloud provider|cloud provider]]. With a [[Glossary#Public cloud|public cloud]], anyone that wants to purchase cloud services can access and use resources. The general public availability is a key difference between public and private clouds.

## Hybrid cloud

A [[Glossary#Hybrid cloud|hybrid cloud]] is a computing environment that uses both public and private clouds in an inter-connected environment. A [[Glossary#Hybrid cloud|hybrid cloud]] environment can be used to allow a [[Glossary#Private cloud|private cloud]] to surge for increased, temporary demand by deploying [[Glossary#Public cloud|public cloud]] resources. [[Glossary#Hybrid cloud|Hybrid cloud]] can be used to provide an extra layer of security. For example, users can flexibly choose which services to keep in [[Glossary#Public cloud|public cloud]] and which to deploy to their [[Glossary#Private cloud|private cloud]] infrastructure.

The following table highlights a few key comparative aspects between the [[Glossary#Cloud model (deployment model)|cloud models]].

|**[[Glossary#Public cloud|Public cloud]]**|**[[Glossary#Private cloud|Private cloud]]**|**[[Glossary#Hybrid cloud|Hybrid cloud]]**|
|---|---|---|
|No capital expenditures to scale up|You have complete control over resources and security|Provides the most flexibility|
|Applications can be quickly provisioned and deprovisioned|Data isn't collocated with other tenants' data|You determine where to run your applications|
|You pay only for what you use|Hardware must be purchased for startup and maintenance|You control security, compliance, or legal requirements|
|You don't have complete control over resources and security|You are responsible for hardware maintenance and updates||

## Multicloud

A fourth, and increasingly likely scenario is a [[Glossary#Multicloud|multicloud]] scenario. In a [[Glossary#Multicloud|multicloud]] scenario, you use multiple [[Glossary#Public cloud|public cloud]] providers. Maybe you use different features from different [[Glossary#Cloud provider|cloud providers]]. Or maybe you started your cloud journey with one provider and are in the process of migrating to a different provider. Regardless, in a [[Glossary#Multicloud|multicloud]] environment you deal with two (or more) [[Glossary#Public cloud|public cloud]] providers and manage resources and security in both environments.

## Azure Arc

[[Glossary#Azure Arc|Azure Arc]] is a set of technologies that helps manage your cloud environment. [[Glossary#Azure Arc|Azure Arc]] can help manage your cloud environment whether it's a [[Glossary#Public cloud|public cloud]] solely on Azure, a [[Glossary#Private cloud|private cloud]] in your datacenter, a hybrid configuration, or even a [[Glossary#Multicloud|multicloud]] environment running on multiple [[Glossary#Cloud provider|cloud providers]] at once.

## Azure VMware Solution

What if you're already established with VMware in a [[Glossary#Private cloud|private cloud]] environment but want to migrate to a public or [[Glossary#Hybrid cloud|hybrid cloud]]? [[Glossary#Azure VMware Solution|Azure VMware Solution]] lets you run your VMware workloads in Azure with seamless integration and scalability.
